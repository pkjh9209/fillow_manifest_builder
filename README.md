# Fillow 매니페스트 빌더

`fillow_diary`의 에셋 매니페스트(`.json`)를 이미지 위에 칸을 칠해서 만드는 도구.

## 실행

**`index.html`을 더블클릭**하면 끝. 설치·빌드·서버 없음.
폴더 직접 저장 기능은 Chrome / Edge에서만 동작한다 (그 외 브라우저는 다운로드로 폴백).

## 쓰는 순서

1. **이미지를 창에 끌어다 놓는다** (또는 `이미지 열기` / `Ctrl+V` 붙여넣기)
   - `imgW`/`imgH`와 `id`, 파일명이 자동으로 채워진다.
   - 상단에 `격자 3 × 3칸 · 한 칸 = 원본 16.00px`이 뜬다.
2. **`적용 A`(자동 추정)를 눌러 대략 칠한다**
   - 불투명 픽셀이 칸의 10% 이상이면 칠한다. 슬라이더로 조절.
   - ⚠ **그림자·카펫처럼 지나갈 수 있어야 하는 칸은 직접 지운다.** 자동 추정은 출발점일 뿐이다.
3. **브러시로 다듬는다**
   - 이미 칠해진 칸에서 드래그를 시작하면 그 드래그 내내 **지우기**로 동작한다.
   - `사각형 R`은 드래그 범위를 한 번에 채우고, `Alt`+드래그면 비운다.
4. **오른쪽 폼을 채운다** — `name`은 필수(언어별). `category`가 `map`이면 `kind`도 필수.
   - `name`/`desc`는 **한국어·영어를 따로** 적는다. 비워두면 그 언어에서 화면에 10자리 난수가 뜬다.
   - 색을 바꿀 수 있는 에셋이면 `shader 색상 변경`을 켠다 (아래).
5. **검증 패널에 ✖(에러)가 없는지 본다** — 있으면 저장 버튼이 잠긴다.
6. **`폴더 지정해 저장`** → `public/asset/<카테고리>/<폴더>` 선택
   - 이미지와 `.json`이 **같은 이름으로 함께** 저장된다.
7. **`npm run build:inventory`** 실행.

## 단축키

| 키 | 동작 |
|---|---|
| `B` / `E` / `R` | 브러시 / 지우개 / 사각형 |
| `A` | 자동 추정 |
| `G` | 격자 표시 토글 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 되돌리기 / 다시 |
| `Ctrl+V` | 클립보드 이미지 붙여넣기 |

## 화면에서 꼭 봐야 할 것

**흰 실선 = 이미지 경계, 노란 점선 = 격자 경계.** 이 둘은 대개 어긋난다.

칸 수는 `Math.round(imgW × 배율 / 16)`으로 정해지기 때문에, 16의 배수가 아닌 이미지는
격자가 그림보다 크거나 작다. 버그가 아니라 반올림 결과이고, 게임도 똑같이 계산한다.

- `default_desk` 46×46 → 3×3칸(48px) — 격자가 **2px 크다**
- `default_carpet` 52×36 → 3×2칸(48×32px) — 격자가 **4px 작다** (그림 오른쪽·아래가 격자에 안 잡힘)

하단 상태바에 이 차이가 항상 숫자로 표시된다.

## 공통 키 세트

**모든 매니페스트가 같은 키를 갖는다.** 안 쓰는 키는 생략하지 않고 `null`로 남긴다.
파일을 열었을 때 항상 같은 모양이라 "이 에셋은 회전이 되나?"를 키 유무로 추측하지 않아도 된다.

```jsonc
"kind": null, "footprint": null, "frameW": null, "frameH": null,
"rotation": null, "shader": null
```

- **`null`을 쓸 수 없는 키**: `id` · `name` · `category` · `imgW` · `imgH` (+ `category`가 `map`이면 `kind`)
  - 특히 `name`이 비면 화면에 **10자리 난수**가 뜬다.
- **`false`는 쓰지 말 것.** `acquisition: false`는 "알 수 없는 값"으로 읽혀
  **`shop`(유료)으로 강등된다** — 무료 아이템이 상점 아이템이 되어 버린다.
- **중첩 객체는 통째로 `null`.** `"shader": { "type": null, "groups": [] }` 처럼
  껍데기만 남기면 빌드가 "쓰려다 실패한 설정"으로 읽고 경고를 뱉는다.

## footprint를 null로 두는 경우

칠한 칸이 **격자 전체와 같으면 `footprint`를 `null`로 출력한다.**
게임이 어차피 같은 값을 기본값으로 계산하기 때문이다 (`RoomScene.getItemFootprint`).
직사각형 가구는 `전체 채움`만 눌러도 되고, 사실 아무것도 안 칠해도 결과가 같다.

**ㄱ자 책상·L자 소파처럼 이미지 안에 빈 칸이 있는 것만** 실제로 칠할 가치가 있다.
굳이 사각형도 명시하고 싶으면 `꽉 찬 사각형이어도 명시해서 출력`을 켠다.

## ⚠ 에셋을 교체할 때

`vercel.json`이 `/asset/**`에 **1년 immutable 캐시**를 건다.
같은 파일명으로 그림만 바꾸면 **이미 그 파일을 받아간 유저에게 1년간 반영되지 않는다.**

- 저장하려는 폴더에 같은 파일명이 있으면 빌더가 막고 경고한다.
- `_v2` 버튼으로 새 파일명을 만든다.
- **`id`는 절대 바꾸지 않는다.** 저장된 배치(`placements[].item`)가 `id`로 아이템을 찾기 때문에,
  바꾸면 유저 방에 놓여 있던 그 가구가 통째로 사라진다.

## 상단 TILE / 배율 입력창

`mapConfig.js`의 `TILE`(16)과 `TEST_ASSET_SCALE.multiplier`(1)를 그대로 옮겨 적은 값이다.
**다이어리 쪽에서 이 값을 바꾸면 여기도 같이 바꿔야 한다.** 격자가 통째로 달라진다.

배율은 **정수만** 받는다. 소수를 넣으면 한 칸이 원본 12.31px 같은 소수가 되어
사람이 그림을 보고 칸을 셀 수 없게 되고, 도트도 반 픽셀에 걸쳐 뭉개진다.

## 자가 테스트

`index.html?test=1`로 열고 콘솔(F12)을 보면 격자 계산·직렬화 테스트 21개가 돈다.
탭 제목이 `✓ 21 PASS`면 정상. `mapConfig.js`를 손댔을 때 이걸로 먼저 확인한다.

## shader (색상 변경)

`셰이더 색상 변경 사용`을 켜면 부위(group)마다 이렇게 지정한다.

- **바꿀 색**: `OUT · SHD · BASE · LIT · HI` 다섯 단계에 각각 색을 고른다.
  선택지는 **이 그림에 실제로 쓰인 색**뿐이다. 손으로 hex를 적을 수 없게 막아둔 이유는,
  팔레트 스왑이 틀려도 예외가 안 나고 "그냥 색이 안 바뀌기" 때문이다.
  오타 하나로 조용히 기능이 죽는 것을 UI 단계에서 차단한다.
- **고를 수 있는 색**: 방꾸미기 팔레트 38색 중에서 고른다. 색 위에 마우스를 올리면
  실제로 어떻게 보일지 캔버스에 미리보기가 뜬다 (게임 셰이더와 같은 계산).
- 단계를 잘못 넣으면(예: LIT 색을 BASE 자리에) 검증 패널이 경고한다.

램프 5단계는 메인색 하나에서 자동으로 유도되므로 색은 **BASE 하나만** 고르면 된다.
아웃라인도 그 계열의 OUT으로 같이 어두워진다.

> 이미지를 새로 올리면 고른 `바꿀 색`이 초기화된다. 그림이 바뀌면 색 목록도 바뀌기 때문이다.

## 아직 없는 것

**`rotation`(n/e/s/w 방향별 이미지)은 지원하지 않는다.**
방향마다 이미지·크기·footprint가 따로라 편집기가 사실상 4벌 필요해서 2차로 미뤘다.
회전 에셋은 당분간 `.json`을 직접 쓰거나, 이 빌더로 방향별 footprint를 하나씩 뽑아
손으로 합치는 식으로 쓴다.

`id` 중복 검사도 없다. 새 `id`가 기존 에셋과 겹치지 않는지는 직접 확인해야 한다.
