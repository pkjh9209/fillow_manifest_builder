# Fillow 매니페스트 빌더 (아이소메트릭)

방꾸미기 에셋의 매니페스트(`.json`)를 그림 위에 점유 마름모를 띄워 놓고 만드는 도구.
`fillow_diary`(앱)와 `fillow_simulator`(에셋 확인용 시뮬레이터) 양쪽 규격을 지원한다.

## 실행

두 가지 방법이 있다.

| 방법 | 할 수 있는 것 |
|---|---|
| **`start.bat`** (= `node server.mjs`, http://localhost:5181) | 아래 전부 + **📥 받은 에셋** · **[다이어리에 추가]** |
| `index.html` 더블클릭 | 그림을 끌어다 놓고 매니페스트 만들기 · 폴더 지정해 저장 (예전과 같음) |

폴더 직접 저장은 Chrome / Edge에서만 동작한다 (그 외 브라우저는 다운로드로 폴백).

## 에셋 흐름 (시뮬레이터 → 빌더 → 다이어리)

```
fillow_simulator  [✓ 검수 완료]  ──복사──▶  fillow_manifest_builder/inbox/<하위 경로>/
                                                   │  📥 받은 에셋에서 열기 → 다듬기 → [받은 폴더에 저장]
                                                   ▼
                                  [다이어리에 추가] ──▶  fillow_diary/public/asset/<하위 경로>/
                                                   │     + build-inventory 자동 실행
                                                   ▼
                                  fillow_manifest_builder/done/<하위 경로>/   (넣은 것 기록)
```

- 세 폴더가 나란히 있어야 한다 (`Desktop\fillow_simulator`, `fillow_manifest_builder`, `fillow_diary`).
  다른 곳이면 `node server.mjs --diary <경로>` / 시뮬레이터는 `--builder <경로>`.
- **id 겹침**: 다이어리에 같은 id의 다른 그림이 있으면 막고 두 가지를 고르게 한다.
  - **새 id로** — 다이어리·빌더에서 안 쓰는 다음 번호를 제안한다 (`furniture-chair-01` → `furniture-chair-02` …). 새 에셋이면 이쪽.
  - **기존 것 교체** — id는 그대로, 다이어리 파일을 이 그림으로 바꾼다. 그림이 바뀌면 파일명도 바꿔야 한다(캐시) → `_v2`.
- 받은 에셋의 매니페스트는 PixelLab 자동 생성이라 이름이 `소파 03`처럼 임시다. 다이어리에 넣기 전에 이름·설명을 채운다.
- `pixellab` 같은 추가 키는 다이어리 매니페스트에 남지만 앱 번들(`assetInventory.js`)에는 들어가지 않는다.
- `back`(뒷모습)은 같이 복사된다. 다이어리는 아직 뒷모습 회전을 쓰지 않는다 (앞모습 + 좌우 반전).

## id · 파일명 · 분류 (type / tags)

- id 규칙: `<fur|dec|etc|map>-<type>-<5자리 번호>` (예: `fur-armchair-00013`, `map-floor-00001`). 파일명 = id.
  번호는 **카테고리 전체에서** 이어 센다. 기준은 다이어리 `src/data/taxonomy.js` 하나다.
- `start.bat`으로 열면 type 선택지·태그 칩이 그 파일에서 나오고, **[자동]** 이 다이어리·빌더·시뮬레이터를
  모두 훑어 다음 번호 id를 주고 파일명도 맞춘다. (시뮬레이터가 다른 곳이면 `node server.mjs --sim <경로>`)
- 받은 에셋을 열 때 type이 비어 있으면 폴더 이름(`furniture/seating/armchair/…`)으로 채운다.
- type·tags는 **비워도 된다** (빈 type = 미분류, 키를 적지 않음). [다이어리에 추가] 때 type이 비어 있으면 한 번 확인한다.
- 태그 목록은 지금 비어 있다. `taxonomy.js`의 `TAGS`에 추가하면 칩으로 나타난다.
- 더블클릭(`index.html`)으로 열면 분류 목록과 자동 번호가 없다 — id 끝 5자리를 직접 고친다.

## 먼저 정할 것: 칸 규격 (헤더 오른쪽)

| 선택 | 칸 | 그림 폭 | 그림 폭 검사 | 바닥 타일 |
|---|---|---|---|---|
| **16 × 8 · 시뮬레이터·다이어리** (기본) | 16×8 마름모 | `(w + h) × 8` | 좁으면 안 됨. 넓으면 좌우 여백이 같아야 함 | 2:1이고 폭이 16의 배수 (16×8, 32×16 …) |
| 32 × 16 · 예전 다이어리 (전환 전) | 32×16 마름모 | `(w + h) × 16` | 정확히 같아야 함 (`build-inventory`가 경고) | 정확히 32×16 |

같은 그림이라도 칸 크기가 다르면 `w`/`h` 숫자가 2배 차이 난다 (다이어리 2×1 = 시뮬레이터 4×2).
시뮬레이터가 16×8로 먼저 옮겨 가는 중이라 기본값은 16×8이고, 고른 값은 브라우저에 기억된다.
규격을 바꾸면 지금 `w×h`가 그림과 안 맞을 때만 바닥 모양 추정치로 다시 잡아 준다.

## 쓰는 순서

1. **그림을 창에 끌어다 놓는다** (또는 `열기` / `Ctrl+V`)
   - 기존 에셋을 고칠 때는 **PNG + 같은 이름의 `.json` + `_back.png`를 한꺼번에** 놓는다. 폼이 그 JSON으로 채워진다.
   - 새 그림이면 `id`·파일명이 자동으로 채워지고, `w×h`는 바닥 모양으로 추정한 값이 들어간다.
2. **점유 칸(`w × h`)을 맞춘다**
   - 그림 폭에서 `w + h`가 정해지므로 **나누는 방법만 고르면 된다** (`1×5`, `2×4` … 버튼, 초록 점 = 추천).
   - 캔버스의 청록 마름모가 그림의 바닥(다리 끝·밑면)과 맞으면 정답이다.
   - `w` = 왼쪽-아래 변의 칸 수, `h` = 오른쪽-아래 변의 칸 수.
3. **그림을 정리한다** (필요할 때만)
   - 아래 빨간 점선 = **그림 아래 투명 여백**. 방에서 바닥 위로 떠 보이므로 `여백 자르기`로 지운다.
   - `규격 폭 패딩`은 그림이 규격보다 좁을 때 좌우에 투명 픽셀을 채운다. `원본으로`로 되돌릴 수 있다.
4. **`flippable` / `flat` / 뒷모습**을 정한다.
   - **막힌 칸**(`blockCells`): 책장처럼 높은 그림이 점유 칸 밖(주로 뒤쪽)을 덮으면 `막힌 칸 편집`(**B**)을 켜고
     캔버스에서 그 칸을 클릭/드래그한다 (빨간 칸). 다른 가구가 그 칸에 못 들어오고 캐릭터도 못 지나간다.
     반전은 자동으로 따라간다. **이 키는 빌더에서만 설정한다** (직접 적지 않는다).
5. **이름·설명(한국어/영어)·shader**를 채운다.
6. **검증 패널에 ✖(에러)가 없는지 본다** — 있으면 저장 버튼이 잠긴다.
7. **`폴더 지정해 저장`** — PNG · JSON · (뒷모습 PNG)가 같은 이름으로 함께 저장된다.
   - 시뮬레이터: `fillow_simulator/assets/pending/<카테고리>/…`. 저장하면 시뮬레이터가 바로 반영한다.
   - 다이어리: `start.bat`으로 열었으면 **[다이어리에 추가]**가 복사와 `build:inventory`까지 해 준다.

## 캔버스 보는 법

| 표시 | 뜻 |
|---|---|
| 청록 마름모 + 안쪽 선 | 점유 칸 (`w × h`). 커서를 올리면 칸 좌표 `[a, b]`가 뜬다 |
| 청록 삼각형 | **앞 꼭짓점** — 엔진이 그림 맨 아래를 맞추는 점 (왼쪽에서 `w × 반칸` 위치) |
| 노란 점선 상자 (입체) | 바닥 마름모를 그림 꼭대기까지 세운 상자. 그림이 이걸 크게 벗어나면 점유 칸 밖으로 튀어나온 것 |
| 노란 점선 세로 상자 | 그림이 규격보다 넓을 때 규격 폭 (시뮬레이터 허용, 가운데 맞춤) |
| 흰 실선 | 그림 경계 |
| 빨간 점선 | 그림 아래 투명 여백 |

`방 미리보기`를 펼치면 작은 방에 게임과 같은 규칙(위치·깊이)으로 놓아 보여 준다.
흰 실루엣은 캐릭터 키(약 49px)다. 오른쪽 방향 카드(앞 / 앞 ⇄ / 뒤 / 뒤 ⇄)를 누르면 그 방향으로 본다.

## 매니페스트 규칙

```jsonc
{
  "id": "furniture-sofa-01",
  "name": { "ko": "2인용 소파", "en": "Two-Seat Sofa" },
  "desc": { "ko": "…", "en": "…" },
  "category": "furniture",          // furniture / deco / etc / map
  "acquisition": "default",
  "qty": 1,
  "w": 4, "h": 2,                   // 점유 칸 수 (배치 아이템만)
  "flippable": true,                // (선택) 좌우 반전 허용 - 반전하면 w↔h
  "flat": true,                     // (선택) 러그처럼 납작함
  "back": "furniture-sofa-01_back.png",  // (선택, 시뮬레이터 전용) 뒷모습
  "shader": { … }                   // (선택) 색상 변경
}
```

- **안 쓰는 선택 키는 적지 않는다.** `false`·`null`도 적지 않는다 (다이어리 `docs/asset-manifest.md`와 같은 관례).
- `image`, `imgW`, `imgH`는 적지 않는다. 파일에서 자동으로 읽는다.
- 탑다운 시절 키(`footprint`, `rotation`, `imgW/imgH`, `frameW/frameH`, `tint`)는 불러올 때 걷어내고 검증 패널에 알린다.
- 불러온 JSON에 이 빌더가 모르는 키(예: `pixellab` 메타)가 있으면 **그대로 뒤에 붙여** 저장한다. `추가 키 버리기`로 뺄 수 있다.

### 맵 아이템 (`category: "map"`)

- `kind: "floor"` — 바닥 타일. 마름모 밖(네 모서리)에 불투명 픽셀이 남아 있으면 경고한다.
- `kind: "wall"` — 벽. `"wall": { "back", "left", "base" }` 세 색으로 그린다 (PNG는 썸네일). 색은 오른쪽 폼에서 고른다.

### 뒷모습 (회전) — 시뮬레이터 전용

`이름_back.png`가 있으면 **앞 → 앞 반전 → 뒤 → 뒤 반전** 4방향으로 돌릴 수 있다.
뒷모습은 앞모습과 점유 칸이 같아야 하므로 **그림 폭이 같아야** 한다 (높이는 달라도 됨).
다이어리는 아직 `back`을 읽지 않는다 (넣어도 무시되고 앞모습만 쓴다).

## shader (색상 변경)

`셰이더 색상 변경 사용`을 켜면 부위(group)마다 이렇게 지정한다.

- **바꿀 색**: `OUT · SHD · BASE · LIT · HI` 다섯 단계에 각각 색을 고른다.
  선택지는 **이 그림(앞·뒷모습)에 실제로 쓰인 색**뿐이다. 손으로 hex를 적을 수 없게 막아둔 이유는,
  팔레트 스왑이 틀려도 예외가 안 나고 "그냥 색이 안 바뀌기" 때문이다.
- **고를 수 있는 색**: 방꾸미기 팔레트 38색 중에서 고른다. 색 위에 마우스를 올리면
  캔버스와 방 미리보기에 실제로 어떻게 보일지 뜬다 (게임 셰이더와 같은 계산).
- 단계를 잘못 넣으면(예: LIT 색을 BASE 자리에) 검증 패널이 경고한다.

> 새 그림을 올리면(JSON 없이) 고른 `바꿀 색`이 초기화된다. 그림이 바뀌면 색 목록도 바뀌기 때문이다.

## 단축키

| 키 | 동작 |
|---|---|
| `A` | 자동 추정 (바닥 모양으로 `w×h`) |
| `F` | 반전해서 보기 (`flippable`일 때) |
| `G` | 칸 선 토글 |
| `V` | 입체 가이드 토글 |
| `Ctrl+V` | 클립보드 이미지 붙여넣기 |

## 자동 추정은 출발점이다

그림 각 열의 가장 아래 픽셀이 마름모의 아래 두 변과 얼마나 맞는지로 점수를 매긴다.
밑면이 꽉 찬 가구(침대·소파·러그)는 거의 정확하고, **다리 달린 책상처럼 바닥에 닿는 곳이 적은 그림은
"확신 낮음"으로 표시된다** — 그때는 다리 끝이 마름모 꼭짓점에 닿는 분할을 눈으로 고른다.
지금 값과 추천이 크게 다르면 검증 패널이 알려 준다 (확신이 높을 때만).

## ⚠ 다이어리에 넣을 때: 에셋 교체 규칙

다이어리 `vercel.json`이 `/asset/**`에 **1년 immutable 캐시**를 건다.
같은 파일명으로 그림만 바꾸면 **이미 그 파일을 받아간 유저에게 1년간 반영되지 않는다.**

- 다이어리 규격일 때 저장 폴더에 같은 파일명이 있으면 빌더가 경고한다. `_v2` 버튼으로 새 파일명을 만든다.
- **`id`는 절대 바꾸지 않는다.** 저장된 배치(`placements[].item`)가 `id`로 아이템을 찾기 때문에,
  바꾸면 유저 방에 놓여 있던 그 가구가 통째로 사라진다.
- 시뮬레이터는 캐시가 없으므로 덮어써도 된다 (방의 가구가 바로 새 그림으로 바뀐다).

## 자가 테스트

`index.html?test=1`로 열고 콘솔(F12)을 보면 기하·추정·직렬화·팔레트 테스트 65개가 돈다.
탭 제목이 `✓ 65 PASS`면 정상. 다이어리 `isoConfig.js`나 시뮬레이터 `src/iso.js`의 칸 규칙을 바꿨으면 이걸로 먼저 확인한다.

## 아직 없는 것

- `id` 중복 검사 — 새 `id`가 기존 에셋과 겹치지 않는지는 시뮬레이터 목록에서 확인한다 (시뮬레이터가 중복을 경고한다).
- 캐릭터 시트(3×3, 64×64) 편집 — 캐릭터는 매니페스트가 아니라 `characterConfig.js`에서 관리한다.
